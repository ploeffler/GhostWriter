Getting started

Getting GhostWriter ready for you is this simple.

From signing in to GitHub to your first chat prompt.

You need a place to keep your books and an AI assistant you want to work with. GitHub stores your files and their revision history. Your chat guides you through developing the book. Here is how to prepare both.

For regular book work, a paid plan for your AI assistant is strongly recommended.

Choose a suitable paid plan from the provider you already want to use. Not every provider calls it “Pro”. Before subscribing, check current usage limits, file features and GitHub capabilities. A subscription alone does not guarantee write access to your repository. You do not need three AI subscriptions.

1 · Sign in to GitHub

Open GitHub. Sign in if you already have an account. Otherwise choose Sign up, follow registration and verify your email address. Complete any additional verification yourself on GitHub.

Your goal: You are signed in and know your GitHub username.

Passwords, verification codes and secret access keys belong in the appropriate sign-in fields, not in your book chat.

GitHub help: creating an account

2 · Create your own GhostWriter copy

Open the GhostWriter template. Your manuscript will go into your own copy, not this public program repository.

  1. Choose Use this template → Create a new repository.
  2. Select your own GitHub account as Owner.
  3. Enter a name, for example my-books.
  4. Choose Private so your book files are not publicly visible.
  5. Leave Include all branches unchecked and select Create repository from template.

A repository is simply your project folder on GitHub. The template already contains the program files. Copy the address of your own repository, such as https://github.com/YOURNAME/my-books.

Your goal: You have a private repository and its address ready.

What about updates and GitHub Actions?

Open Actions in your own repository and check whether workflows may run. GhostWriter's setup instructions call for GhostWriter aktualisieren → Run workflow. The workflow retains its German name (“Update GhostWriter”). Wait for successful completion; a failed run is not a completed update.

The full guide explains optional credentials for updating workflow files. Without these, workflow files remain unchanged during updates, while other program files can still be updated. Enter secret keys only in the designated GitHub secret fields.

3 · Connect the chat you want to use

Sign in to your AI provider. Choose your existing chat application and connect it to your GhostWriter copy. Restrict access to that repository wherever the connection offers this option.

Important: Seeing files in a chat and saving changes on GitHub are separate capabilities. Imported files are enough for joint planning. Automatic saving additionally requires suitable tools and permissions.

I use ChatGPT or Codex

In your OpenAI application, look for the available GitHub app or plugin and connect your account through its sign-in flow. A workspace may require administrator approval. Select your own GhostWriter copy.

ChatGPT, Codex and their different interfaces do not automatically provide the same tools. The startup instructions check whether the current session can read files and has tools to save changes. A connection in another interface does not establish access here.

OpenAI: connect computers and apps · OpenAI: Codex Cloud and GitHub

I use Claude

In the documented chat interface, choose + → Add from GitHub. Sign in to GitHub when prompted and grant access to your private copy. Start with the entry files, particularly README.md and START.md.

The built-in file integration supplies context. Do not assume it also provides write access. Have the available tools checked. If saving is unavailable, you can plan in the chat and transfer results yourself later.

Claude: use the GitHub integration

I use Gemini

The documented web interface on a computer offers Add file → More Uploads → Import code. Enter your repository address. For a private repository, link your authorised GitHub account when prompted.

The import is a snapshot: later repository changes are not automatically synced. According to Google's help, Gemini's GitHub app cannot write to the repository or read it just because you include a URL in a prompt. Import the files before starting. Saving requires a separately supported write connection or transferring the results yourself.

Gemini: import a GitHub repository

Your goal: Your chosen chat has access to the entry files through a connection or a deliberate file import.

4 · Open your prepared chat

Open a new chat in your chosen application. Enable the GitHub connection or add the repository import. Have the address of your own GhostWriter copy ready.

You do not need a separate test request or to copy all of GhostWriter's rules into the chat. They are already in START.md.

Your goal: Your chat and repository address are ready.

5 · Start GhostWriter with just one prompt

Replace the example address with your own repository and send this sentence:

Read the file START.md from the repo https://github.com/YOURNAME/my-books

START.md contains the entry instructions and working rules. When the assistant loads it, those instructions call for checking repository access and permissions that can be established without changes. No second prompt is required. Simply opening this HTML guide does not create a connection.

If access is missing, the assistant explains what needs setting up. With imported files, START.md must be included in the imported material; the repository link does not replace the import.

Does startup check write access too?

Yes: GhostWriter's startup rules call for checking available tools and permissions without changing files. Creating or changing a test file is not part of startup.

Actual saving is confirmed only by the first explicitly authorised change that succeeds. If writing is unavailable, GhostWriter can continue in the chat and provide results for you to transfer.

You do not need to request this separately. It belongs to the workflow in START.md.

How do you know it has started?

GhostWriter recognises your repository and follows its startup rules. A prepared library shows its book shelf, even when no book has been created yet. New book starts book creation. That explicitly confirmed action is separate from subsequently saving the developed book structure.

Use New book to enter your first working title. You do not need a complete plot yet. You develop the topic, audience, style and outline in conversation.

GhostWriter is ready for your first idea.
